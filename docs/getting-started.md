# Ubuntu 启动指南

更新时间：2026-08-24

这是一份按执行顺序编写的操作说明。你不需要理解 C++、GCC、Qt、ELF 等名词；只需从第一步
开始执行，遇到错误时按文末对应的处理方法操作。

## 先看结论

当项目已经成功编译，而且代码没有在编译后发生变化时，以后每次启动只需要：

```bash
cd ~/桌面/A2UI-Qt-Demo
scripts/start_ubuntu_demo.sh
```

如果这条命令提示“未找到合格 ELF”或“目标 ELF 早于当前前端源码或资源”，说明需要先完成
第二步，不能直接启动。

## 第一步：进入项目目录

打开 Ubuntu 图形桌面中的终端，执行：

```bash
cd ~/桌面/A2UI-Qt-Demo
```

后面的命令都在这个目录中执行。不要在纯 SSH 终端中启动界面，除非该连接已经正确配置图形
显示。

## 第二步：确认项目已经编译

先执行：

```bash
if test -x build-gcc-9.3.0/frontend/app/a2ui_qt_demo ||
   test -x build-gcc-7.3.0/frontend/app/a2ui_qt_demo; then
    echo "程序已准备好"
else
    echo "需要编译"
fi
```

### 如果显示“程序已准备好”

跳到第三步。

### 如果显示“需要编译”

项目需要先生成与它兼容的可执行程序。准备好 PowerShell 和 Docker 后，执行：

```bash
pwsh ./tools/build-matrix.ps1
```

这个过程会编译项目并运行测试，可能需要一段时间。成功后，仓库中会出现
`build-gcc-9.3.0` 和 `build-gcc-7.3.0`，然后重新执行本步骤开头的检查命令。

如果终端提示没有 `pwsh` 或 Docker，不要改用系统自带的 `g++` 自行编译；当前机器
还缺少项目要求的构建环境，需要先安装这些工具，或请项目维护者提供一个兼容的构建目录。

## 第三步：配置自然语言编排（可选，只做一次）

如果你希望在界面中输入自然语言来改变布局，执行：

```bash
scripts/configure_demo_provider.sh
```

按照提示输入 API Key。输入过程不会把 Key 显示在终端中，配置成功后以后启动会自动复用。

如果你只想查看默认界面、使用计算器、导入或导出 DSL，可以跳过这一步。没有 API Key 时，
只有自然语言编排不可用，其他功能仍可使用。

## 第四步：启动前检查

第一次启动、重新编译后或代码更新后，建议先执行：

```bash
scripts/start_ubuntu_demo.sh --preflight-only
```

看到类似下面的内容，表示可以启动：

```text
预检通过：GCC 9.3.0 / Qt 5.12.8 / ICU 56 / xcb / Linux Python
```

预检只检查环境，不会打开窗口。若失败，直接根据错误文字查看文末“出现问题时怎么处理”。

## 第五步：启动应用

执行：

```bash
scripts/start_ubuntu_demo.sh
```

启动成功后会看到一个窗口：

- 左侧是自然语言输入、导入、导出、恢复默认排版和诊断按钮；
- 右侧是动态工作区；
- 不会再出现第二个旧版示例窗口。

启动脚本所在的终端需要保持打开。

## 启动后如何使用

工作台分为三个用户可见部分：

- **左侧控制区**：输入自然语言并开始编排，也在这里导入、导出或恢复 Surface。
- **右侧动态 Surface**：显示当前已校验的组件树。内容过宽或过高时可以滚动，顶部会显示
  Surface ID、节点数、来源和状态。
- **诊断区**：左侧底部先显示一行结果摘要。操作失败时可点击“展开诊断详情”查看错误码
  和原始说明。

### 五类组件能做什么

| 组件 | 用户可见功能 |
|---|---|
| Calculator | 用固定按钮执行四则计算；有效结果会请求后端保存 |
| CalculationHistory | 查看最近 50 条计算、修改备注、删除记录和手动刷新 |
| CalculationStats | 显示当前记录数和最新的表达式/结果 |
| Clock | 显示持续运行的时钟，页面重排时保留运行状态 |
| NotePad | 输入临时文本；同一实例被移动时保留未提交草稿 |

Calculator、History 和 Stats 不直接通知彼此。Calculator 把成功结果交给本地后端保存，
History 和 Stats 再各自向后端查询。正常情况下，新结果会在最多 4 秒内出现在后两者中。

### 用自然语言重排

1. 在左侧输入框中输入一条明确要求。
2. 点击“开始编排”。等待时会显示“请求中…”，文档操作按钮会临时禁用，请不要连续重复提交。
3. 成功时会显示“编排成功”和“编排目标已校验并应用”，右侧 Surface 更新。
4. 不支持或请求失败时，摘要会说明能力边界或 Provider 问题；右侧继续保留“最后有效页面”，
   即上一个已通过完整校验并成功提交的 Surface，业务组件可继续使用。

可直接复制的支持示例：

```text
把计算器放左边，历史记录放右边
计算器在上，历史记录在下
统计和时钟做左侧栏，其余放右侧
只用 Row 和 Column 做成上下两行、每行两个区域的 2×2 面板
计算器宽度约为历史记录两倍
再添加一个独立计算器
```

可直接复制的不支持示例：

```text
用 Grid，让历史记录跨两列并支持响应式断点
用可拖动 Dock 停靠统计面板
用 Splitter 让模型控制分隔条
把计算器浮在历史记录上方
给页面设置蓝色背景和自定义字体
添加一个点击后执行脚本的按钮
```

这些请求超出当前 Row/Column、已注册组件和宿主样式边界，应当被拒绝并保留当前页面。

### 导入 DSL

1. 点击“导入 DSL”。
2. 选择一个不超过 64 KiB 的 UTF-8 SurfaceSpec JSON。
3. 后端和 Qt 两层校验都通过后，右侧页面才更新。失败时查看诊断，不要把 LayoutPlan 当作
   SurfaceSpec 导入。

可直接导入的 40 份 Provider 样本位于
[`evaluation-data/provider-valid-surfaces/`](evaluation-data/provider-valid-surfaces/)；分类与注意事项见
[评测数据索引](evaluation-data/README.md)。

### 导出 DSL

1. 当前已有有效 Surface 时，点击“导出 DSL”。
2. 选择目标文件，建议使用 `.json` 扩展名。
3. 应用先请求后端复核当前 Surface，再原子写入。导出内容不包含计算历史、NotePad 文本、
   日志、主题或 Provider Key。

### 恢复默认排版

1. 点击“恢复默认排版”。
2. 受控默认 Surface 通过同一 Qt 校验和原子提交流程应用。
3. 这个操作只恢复组件排列，不清空 SQLite 中的计算记录，也不删除 Provider 配置。

## 第六步：退出应用

使用以下任一方式：

1. 关闭应用窗口；
2. 在启动应用的终端中按 `Ctrl+C`。

脚本会同时关闭它启动的后台服务并释放端口。配置、计算记录和可复用缓存会保留，下一次不必
重新配置。

## 第七步：以后再次启动

只要以下两件事没有变化：

1. `build-gcc-9.3.0` 或 `build-gcc-7.3.0` 没有被删除；
2. 编译完成后没有更新前端代码或界面资源；

以后进入项目目录后直接执行即可：

```bash
scripts/start_ubuntu_demo.sh
```

不需要每次执行配置脚本，也不需要每次执行预检。遇到错误时再执行
`scripts/start_ubuntu_demo.sh --preflight-only` 获取完整诊断。

## 代码变更后怎么做

修改代码、切换分支或拉取新版本前，先关闭应用窗口，或在启动应用的终端中按 `Ctrl+C`。

### 只修改了 Markdown 文档

如果只修改了 `docs/` 下的说明文档，没有修改程序代码、配置或界面资源，不需要重新编译。
下次仍然直接执行：

```bash
scripts/start_ubuntu_demo.sh
```

### 修改或更新了程序代码

如果修改了 C++、Python、CMake、默认界面 JSON、主题资源，或者无法确定改动是否影响程序，
使用下面这套最稳妥的流程：

```bash
cd ~/桌面/A2UI-Qt-Demo
pwsh ./tools/build-matrix.ps1
scripts/start_ubuntu_demo.sh --preflight-only
scripts/start_ubuntu_demo.sh
```

第一条命令重新构建并测试项目；第二条命令只检查启动条件；第三条命令在检查通过后打开应用。
已经保存的 Provider 配置和运行数据不会因为重新构建而丢失。

如果没有重新构建就直接启动，脚本发现界面代码或资源比现有程序更新时，会停止并显示
“目标 ELF 早于当前前端源码或资源”。此时按上面的三条命令操作即可，不要绕过检查。

### 重新构建失败

不要继续启动旧程序。查看构建输出中最先出现的 `error` 或 `FAILED`，保留从该位置到命令
结束的日志，再交给维护者排查。修复后重新执行完整流程。

## 使用别人提供的构建目录

如果兼容的构建程序不在仓库的标准目录中，可以显式告诉启动脚本它在哪里：

```bash
scripts/start_ubuntu_demo.sh --build-dir /完整路径/构建目录
```

预检命令同样需要带上该参数：

```bash
scripts/start_ubuntu_demo.sh --preflight-only --build-dir /完整路径/构建目录
```

不要把 `/tmp` 中的目录当成长期方案。Ubuntu 重启或系统清理后，`/tmp` 中的构建可能消失。

## 出现问题时怎么处理

### 错误：“未找到合格 ELF”

含义：启动脚本没有找到已经编译好的程序。

处理：回到第二步执行检查和编译。如果构建在其他位置，使用 `--build-dir /完整路径/构建目录`。

### 错误：“目标 ELF 早于当前前端源码或资源”

含义：代码或界面文件在上次编译后发生了变化，旧程序不能代表当前代码。

处理：按照“代码变更后怎么做”一节重新构建；核心命令是：

```bash
pwsh ./tools/build-matrix.ps1
```

完成后再次执行预检。不要通过修改文件时间或恢复旧启动脚本来绕过检查。

### 错误：“缺少 DISPLAY”

含义：当前终端无法连接 Ubuntu 图形桌面。

处理：在本机已经登录的图形桌面中打开终端再启动。如果正在使用 SSH，需要先正确配置图形
转发；最简单的办法是在机器本地桌面终端中运行。

### 错误：“回环端口 127.0.0.1:8000 已被外部进程占用”

含义：默认端口正在被其他程序使用。

处理：换一个端口启动，例如：

```bash
scripts/start_ubuntu_demo.sh --port 8010
```

脚本不会擅自关闭占用原端口的程序。

### 错误：“Provider 配置权限过宽”

执行：

```bash
chmod 600 config/provider.local.env
```

然后重新启动。

### 错误：“后端 /health 未就绪”

先查看最后 100 行日志：

```bash
tail -n 100 "${XDG_STATE_HOME:-$HOME/.local/state}/a2ui-qt-demo/backend.log"
```

常见原因是 Python 环境准备失败或依赖不完整。保留日志中的错误信息，再交给维护者排查。

### 窗口能打开，但自然语言编排失败

先确认是否完成第三步。需要重新填写 Key 时，再次执行：

```bash
scripts/configure_demo_provider.sh
```

自然语言请求失败不会影响默认界面、计算器、DSL 导入、导出和恢复默认排版。

### 中文显示成方框

系统缺少中文字体。安装 Noto CJK 或其他中文字体后，关闭应用并重新启动。
