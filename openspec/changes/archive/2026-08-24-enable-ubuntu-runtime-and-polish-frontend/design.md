## Context

现有项目已经在受控 GCC 7.3.0/9.3.0 容器中完成 Qt 5.12.8 ELF 构建，并验证 Ubuntu 22.04 的 Wayland/XWayland 会话可通过 `xcb` 创建真实窗口。仓库包含离线 Qt/ICU/CMake 资源、统一 FastAPI 后端、七场景 Provider 验收脚本和动态 HostShell。SurfaceSpec 导入/导出、恢复默认、单窗口工作台和新主题已经进入当前源码，但仓库中的旧构建目录仍可能保存早于这些功能的 ELF；原 Ubuntu 入口只检查文件、目录和 GCC 版本，因此会把旧二进制误判为可运行的当前构建。

约束来自现有 OpenSpec 合同和 [proposal.md](./proposal.md)：核心依赖与 C++14/ABI 基线不变；Catalog、SurfaceSpec、LayoutPlan 和业务 API 不变；LLM 不获得样式或行为权限；无效更新仍必须保留最后有效 Surface。

## Goals / Non-Goals

**Goals:**

- 用一个可诊断、可重复的入口串联运行预检、Linux 后端、Qt 窗口和确定性清理。
- 保证唯一用户启动入口不会继续运行明显早于当前前端源码和资源的旧 ELF。
- 让运行缓存、数据库、日志和 Linux Python 环境与源码树及 Windows `.venv` 隔离。
- 在不改变编排协议的情况下建立统一、可测试的中文呈现和宿主静态主题。
- 让真实 Provider 重验具备轮换密钥前置条件、七场景门禁和结果防泄漏检查。
- 保持受控 GCC/Qt/C++14 构建基线，同时让后续受控构建产出的测试二进制在任意仓库路径定位 Fixture。
- 让用户能安全导入、导出当前 SurfaceSpec，并随时恢复受控默认排版，所有失败均保留最后有效页面。
- 建立首轮 50 样本的 DSL 合法率、平均响应时间和 p50 基线，以及确定性的合法 DSL 批量导入渲染回归。
- 只保留单一 HostShell，以工程工作台式分区明确隔离编排控制与动态 Surface，并针对不同合法 DSL 优化组件呈现。
- 删除旧入口直接关联且确认无用的代码、测试和产物，并同步最必要的启动文档。

**Non-Goals:**

- 不在 Ubuntu 入口中实现系统 GCC 11 的本机构建，也不把运行入口变成新的工具链管理器。
- 不创建新的布局节点、响应式规则或 SurfaceSpec 展示字段。
- 不用 QML、Graphics View、QtSql、第三方主题库、外部字体包或 Qt Wayland 模块重写界面。
- 不自动获取、轮换或持久化 Provider 密钥，也不在没有新密钥时执行真实外部调用。
- 不让后端保存用户会话或“当前页面”；当前已应用 Surface 的权威状态仍属于 HostShell。
- 不在首轮 50 样本中扩展尾部百分位指标，也不把概率性测评结果伪装成确定性单元测试。
- 不为美观向 SurfaceSpec 增加颜色、字体、像素几何、断点或任意样式字段。

## Decisions

### 1. 新入口复用现有脚本，只增加最小的新旧检查

仓库当前唯一用户入口是 `scripts/run_ubuntu.sh`，但它会选择 2026-08-18 的旧 ELF，而当前 HostShell、导入/导出按钮和主题源码已更新。不存在另一个可直接采用的正确启动脚本，因此新增 `scripts/start_ubuntu_demo.sh`，迁移旧脚本中已经工作的参数、XDG、Qt/ICU、Provider 配置、后端启动和退出清理逻辑，然后删除旧脚本。

新入口继续验证 GCC/Qt/ABI 基线，并在启动前比较目标 ELF 与有限的一组前端输入：`frontend/app`、`frontend/composition`、`frontend/widgets`、`shared/default-surface.json`、顶层/前端 CMake 和构建策略。任一相关文件晚于 ELF 时直接失败并提示执行既有受控构建。该检查足以拦截本次“8 月 18 日二进制 + 8 月 21 日源码”的问题，同时不新增清单生成器、共享验证服务、构建插件或自动编译流程。

入口仍保留“仅预检”和显式构建目录参数，不调用系统 GCC 11。旧脚本不保留包装或别名，仓库内测试和文档直接改用新名称。

### 2. 使用 XDG 用户目录隔离缓存、数据和状态

派生 Qt/ICU 内容与 Linux venv 放在 XDG cache 目录，SQLite 数据放在 XDG data 目录，日志、PID/owner 标记和验收临时结果放在 XDG state 目录；对应 XDG 变量缺失时使用 Linux 约定的用户目录回退。仓库 `.cache` 仅作为离线归档和已准备资源的只读来源，不把新的运行产物写回源码树。

缓存键包含 Qt/ICU 版本和来源归档摘要。命中时校验标记后复用，不命中时从仓库离线资源解压到临时目录，校验成功后原子替换目标缓存。只要离线资源可用就不运行 Qt `.run` 安装器。Linux venv 的缓存键额外包含 Python 主次版本与 `backend/requirements.txt` 摘要，确保 requirements 不变但缓存失效可控。

备选方案是使用项目内忽略目录，路径更直观，但容易与 Windows `.venv`、构建缓存及 Git 工作区状态混淆，也不利于多个 worktree 复用，因此选择 XDG 用户目录。

### 3. 由父入口拥有子进程并执行精确清理

入口在确认端口空闲后启动后端，记录实际 PID 和进程启动标识，只对自己创建且身份仍匹配的进程发送终止信号。shell trap 处理 Qt 正常退出、SIGINT、SIGTERM 和启动失败：先请求子进程正常结束，超时后再对匹配的自有 PID 升级处理，最后验证端口释放。它绝不依据端口号杀死未知进程。

Qt 主程序只创建动态 HostShell，因此关闭唯一窗口即可进入统一清理路径。保留截图模式作为非交互冒烟，但只捕获工作台和代表性 DSL，不再创建或保存 LegacyToolboxWindow；正常 Ubuntu 入口不设置 offscreen 或自动退出变量。

### 4. 测试 Fixture 采用运行时仓库根解析

Qt 测试新增共享的测试路径解析逻辑：优先使用显式 `A2UI_TEST_SOURCE_ROOT`，验证目标下存在预期 `shared/fixtures` 和 schema；否则从当前工作目录、测试可执行文件所在构建目录向上发现仓库标记；编译时 `A2UI_SOURCE_DIR` 只作为最后兼容回退。所有读取 Fixture 与 `docs/llm-acceptance-results.json` 的 Qt 测试改用该解析器。

Ubuntu 回归入口显式传入当前仓库根并直接使用当前仓库作为后端测试工作目录，从而不需要在主机创建 `/workspace` 符号链接或绑定映射。备选方案是继续为 `/workspace` 建映射，但它需要额外权限、会隐藏产物不可移植问题，因此不采用。

### 5. 主题采用“受控界面工作台”视觉语言并编译进 Qt 资源

现有深海军蓝加青蓝的方案容易落入通用 AI 控制台模板，且大面积同色卡片没有编码控制区、动态区域和组件层级。改用冷灰工作台画布 `#E9EDF2`、墨黑控制栏 `#17202A`、纸白 Surface 舞台 `#F9FBFD`、指令蓝 `#2D6CDF`、成功绿 `#16866B` 和错误红 `#C64B40`。颜色通过固定语义 token 进入静态 QSS，不由 DSL 决定。

字体分为三个可信角色：Noto Serif CJK SC SemiBold 仅用于工作台标题和空状态标题，以克制的衬线形成产品识别；Noto Sans CJK SC 用于正文和业务控件；Noto Sans Mono CJK SC 用于 Surface ID、节点数、来源、错误码和计时数据。系统缺少首选字体时按角色回退到可显示中文的系统字体，不打包外部字体。

新增 Qt resource 中的静态 QSS 和小型主题初始化模块，在 `QApplication` 创建后加载。不使用透明模糊、阴影动画或新图形依赖；视觉上的一次“冒险”集中在少量衬线标题与带真实元数据的 Surface 舞台框，其余控件保持安静、紧凑和工程化。

主题只根据应用设置的固定 objectName、Qt widget 类型和可信动态属性选择样式；不读取 Catalog、SurfaceSpec、LayoutPlan 或 LLM 输出。QSS 加载失败时回退系统样式并给出本地诊断，不能阻止协议校验或业务功能。

备选方案是让协议携带 theme token，但这会扩大 AI 展示权限并改变 Schema，明确不采用。

### 6. 业务 QWidget 自身提供可信卡片标题和自适应尺寸策略

五类共享业务 QWidget 的根对象作为卡片边界，在各自已有顶层布局中加入应用维护的中文标题，并设置固定 objectName/状态属性供全局主题使用。每类组件补充合理的 minimumSizeHint、size policy、内部 stretch 与窄宽度下的控件排列，使其在 Row/Column、深层嵌套和权重布局中保持有效几何；无法同时容纳的整体内容仍由既有 Surface `QScrollArea` 承接。稳定 ID 继续绑定原业务 QWidget，Reconciler 的复用、焦点恢复和状态保持路径不变。

备选方案是在 Renderer 外包一层卡片容器。虽然也能保持叶子对象，但会增加暂存、placeholder 替换和父对象生命周期的复杂度，并可能使根叶子场景行为分叉，故不采用。只使用全局边框而没有标题的方案信息层级不足，也不采用。

### 7. HostShell 使用可调双区工作台和默认折叠诊断区

HostShell 使用水平 `QSplitter` 形成约 280:620 的默认分区。左侧墨黑控制栏承载标题、自然语言输入、编排按钮、导入/导出/恢复默认操作、最新状态和折叠诊断；右侧纸白 Surface 舞台承载唯一的动态 Renderer。900×700 下优先保证控制栏操作完整，Surface 内容不足时滚动；分隔条可由用户调整但设置合理最小宽度。

```
┌────── 编排与文档控制栏 ──────┬───────── 动态 Surface 舞台 ─────────┐
│ 指令输入 / 编排状态           │ DYNAMIC SURFACE · main · 7 nodes  │
│ 导入 · 导出 · 恢复默认        ├───────────────────────────────────┤
│ 最新结果 / 折叠诊断           │         Renderer 动态内容          │
└───────────────────────────────┴───────────────────────────────────┘
```

Surface 舞台标题显示 `surfaceId`、节点数、来源（默认/模型/导入）和最近应用状态，这些信息全部由 HostShell 从已验证文档计算。该舞台框是页面唯一的签名元素，它真实表达“受控 DSL 正在这里生效”，而不是无意义装饰。状态模型保持就绪、请求中、成功、失败四类，按钮禁用逻辑沿用现有请求生命周期；界面不增加散落动画，只通过文字、边界和焦点状态表达变化。

诊断区采用 checkable 标题按钮加限高 `QPlainTextEdit`：默认折叠，仅显示最新中文摘要与是否有详细信息；展开后显示原错误码、原始诊断及对应中文解释，保留现有最大 block 数。选择折叠区而非固定限高常显或抽屉，是因为 Qt Widgets 下实现简单、键盘可达、不会引入叠层，并能在 900×700 中为 Surface 保留更多空间。

内部英文诊断通过宿主维护的错误码/已知诊断映射增加中文解释，原值附在详情中，不修改服务端、Validator 或测试依赖的文本。

### 8. 缩放、不同 DSL 与交互状态通过布局和自动化检查共同约束

布局继续使用 Qt layout、size policy 和现有 `QScrollArea`，不引入像素几何到协议。主题为 hover、focus、disabled、success、error 设置非颜色单一线索，例如边框、文字和固定状态标签。Qt 测试检查 objectName、分区、折叠行为、状态转换、主题来源、文档操作和重排后对象身份；固定种子 DSL 批次检查组件数量、类型、有效几何、重叠、滚动和 Qt 关键告警。代表性结构在 100%、125%、150% 缩放环境执行单窗口截图/几何冒烟。

### 9. Provider 密钥映射与审计写入均在边界处防泄漏

Ubuntu 入口仅为其子进程构造环境：若存在 `deepseek_api` 且未设置 `A2UI_LLM_API_KEY`，在不回显值的情况下完成一次映射；应用本身的三变量合同不变。脚本和文档只出现占位符。是否已轮换属于操作者提供密钥前的安全前置条件，流程不尝试识别或恢复旧密钥；没有明确提供的新密钥时跳过真实调用并报告“未验收”，而不是复用旧结果。

验收 runner 保持七个场景和既有 Parser/Compiler/Validator 链路，在写文件前递归扫描序列化报告，拒绝出现当前密钥、`Authorization`/`Bearer` 模式或已知敏感字段。结果先写入 XDG state 的临时文件，通过七场景与防泄漏门禁后才原子更新明确指定的审计目标；API Key 永不进入异常文本或命令输出。

备选方案是从 `.env` 读取密钥，但会产生持久化和误提交风险，明确不采用。

### 10. Demo 本地配置与请求超时采用宿主白名单

为降低 Demo 操作成本，允许 `config/provider.local.env` 保存 endpoint、model、API Key、Provider
超时和 Qt 编排超时。该文件由配置脚本通过隐藏输入创建、Git 忽略且权限固定为 `0600`；
运行入口不使用 `source`，只解析预定义键，环境变量具有更高优先级。仓库提交的 example 只含
占位符。这样可以实现一次配置后直接启动，同时避免把有效密钥写入 Git 历史。

Qt CompositionClient 不再固定使用 10 秒预算。Ubuntu 入口默认设置 Provider 90 秒、Qt 编排
120 秒，Qt 预算始终留有网络和后端编译余量；两者仍可通过白名单配置或环境变量调整。后端
完成 200 时 Qt 因较短本地计时器提前 abort 的竞态由此消除。

### 11. Surface 文档接口保持后端无状态并复用同一校验边界

新增三个回环 HTTP 接口：`POST /surface/import` 接收不超过 64 KiB 的原始 `application/json` 文档，完成 JSON、封闭字段、Schema、Catalog 与图结构校验后返回完整 Surface；`POST /surface/export` 接收当前 Surface，复核后以稳定缩进、UTF-8 和末尾换行返回 `application/json` 附件；`GET /surface/default` 返回受控默认 Surface。三个接口都不保存会话，也不决定 Qt 当前页面。

后端把现有 `validate_surface_spec` 提升为编排、导入、导出和默认文档共同使用的校验边界，并统一返回 `error.code/message/diagnostics`。导入文件路径不会发送到后端，服务只接收内容；导出响应不包含 QWidget 状态、业务数据、日志或主题。

HostShell 增加文档客户端和显式状态来源。导入流程为：本地选择与大小检查 → 调用导入接口 → Renderer 在暂存树中构建 → 成功后同时提交 QWidget 树和 `currentSurfaceJson_`。任何一步失败都不改变二者。导出流程先调用服务端复核，再通过 `QSaveFile` 原子写入用户选择的位置；用户取消不视为错误。选择“后端无状态 + 前端持有当前 Surface”而不是服务端会话，是为了避免多窗口/多客户端状态竞态，并与现有 `/compose` 请求显式携带 `currentSurface` 的合同一致。

```
文件 JSON ─▶ /surface/import ─▶ 共享校验 ─▶ Renderer 暂存 ─▶ 原子提交
                    │                │              │
                    └──── 任一失败 ──┴──────────────┴──▶ 保留最后有效页面

当前 Surface ─▶ /surface/export ─▶ 共享校验 ─▶ QSaveFile
```

### 12. 默认 Surface 使用单一受控源，Legacy 窗口从生产路径移除

把当前硬编码初始 Surface 提取为一个版本控制下的默认 JSON 源，同一文件同时进入 Qt 只读 resource 并供后端 `/surface/default` 加载。应用启动和“恢复默认排版”都通过同一校验与 Renderer 事务路径；按钮优先使用本地只读 resource，使 Provider 或网络不可用时仍能恢复，后端接口用于外部调用、集成测试和一致性校验。

删除 `main.cpp` 对 LegacyToolboxWindow 的创建、移动和截图捕获，并从生产 CMake source、专用测试和运行文档中移除该类。保留第二个窗口但默认隐藏会继续制造维护与生命周期分叉，因此不采用。固定布局的教学价值由可导出、可导入、可恢复的默认 Surface 替代。

### 13. 七场景门禁与五十样本基线分离

七场景 runner 继续承担确定的功能门禁：六个支持场景必须满足结构/稳定 ID 断言，不支持场景必须返回 `unsupported_layout`。另建基线 runner 对版本化语料执行恰好 50 个串行样本，默认并发 1 以模拟单用户 HostShell。每个样本用单调时钟记录 Provider 调用和 `/compose` 端到端耗时，并标记传输、超时、解析、语义、编译、最终校验中的首个失败阶段。

合法率以 50 为固定分母：只有最终 SurfaceSpec 通过完整校验才算合法；Provider 已响应但后续失败仍计为不合法。平均值和 p50 同时对全部 50 样本报告，并补充成功样本子集，避免只看成功请求造成幸存者偏差。首轮只采用这两个延迟指标；若外部中断导致不足 50 个最终样本，只生成“未完成”报告，不更新正式基线。

报告记录语料版本、样本 ID、模型、endpoint、温度、超时和运行时间，并复用敏感字段扫描与原子写入。原始响应可以进入受控审计，但 API Key、Authorization/Bearer、环境变量值和本地配置路径不得进入结果。

### 14. 合法 DSL 生成器与问题清单构成确定性回归闭环

新增无第三方依赖、固定 seed 的 SurfaceSpec 生成器，根据 Schema 与 Catalog 构造合法树，并输出覆盖清单。覆盖维度包括根叶子/空容器、Row/Column 嵌套、节点数和深度边界、五类组件、允许的 Calculator 重复实例、四档 gap、四档 align、六档 justify，以及合法 weight 与 `justify=start` 组合。生成器本身先由服务端 Validator 验证，防止把错误 Fixture 当成 Renderer 缺陷。

后端批次通过 TestClient 调用 `/surface/import`；Qt 批次在同一 HostShell 依次应用响应，断言组件类型/数量、有效几何、无主要控件重叠、滚动可达、无崩溃和关键 Qt 告警。每个结构类别与边界只保留少量代表性截图，避免维护大规模脆弱像素 golden；结构与几何断言承担主要回归职责。

测评输出再聚合成问题清单，字段固定为类别、频率、影响、最小复现、证据、责任边界、下一步和当前兜底。立即兜底统一为：无效导入/模型结果不提交、Renderer 失败保留最后有效页面、慢请求持续显示明确状态且不盲目重试、用户可导出证据或恢复默认。后续优化优先处理高频且高影响类别，但不得以放宽 Schema 或绕过校验换取通过率。

### 15. 只删除确认存在且无用的旧内容

当前 `frontend/app/main.cpp` 和 `frontend/app/CMakeLists.txt` 已经只构建、启动 `HostShell`，生产源码中没有 `LegacyToolboxWindow` 文件，因此不安排前端重构。实施时只再做一次引用检查：若发现旧窗口源码、专用 CMake source 或只服务旧窗口的测试且已无调用，则删除；若 Legacy 只存在于旧 ELF、CTest 或截图，则清理相应生成物，不改动当前 HostShell、业务 QWidget 或 Renderer。

启动侧直接删除 `scripts/run_ubuntu.sh`，把 `tests/runtime/test_run_ubuntu.sh` 改名并调整到新入口，把 `tests/runtime/test_runtime_lifecycle.sh` 的调用替换为新脚本。`fake_backend.py`、`fake_qt.sh` 等仍被测试使用的辅助文件保留，不抽取新的公共 helper。

### 16. 只更新直接相关的启动文档

必须更新 `docs/getting-started.md` 和仓库现有的 `docs/README.md`。另外，`docs/ubuntu-runtime.md`、`docs/toolchain-matrix.md` 当前直接引用旧命令，也同步替换；其他文档只有在仍包含旧命令、双窗口或错误启动结论时才修改。文档说明新入口、旧构建被拒绝时如何重新执行既有受控构建，以及启动后应看到单一 HostShell、导入/导出/恢复默认按钮和新主题。

## Risks / Trade-offs

- [旧 ELF 可能依赖比预期更多的容器运行库] → 预检使用动态链接解析和插件加载检查逐项报告；只从版本锁定缓存补齐 Qt/ICU，不用系统编译器重建掩盖问题。
- [XDG 缓存损坏或来源归档更新] → 使用来源摘要、版本化目录、临时解压和原子替换；失败时保留上一个已验证缓存并停止启动。
- [全局 QSS 可能意外影响业务控件尺寸] → 不设置业务控件固定几何，保留 size policy；在三档缩放和 900×700 下增加视觉/几何回归。
- [给业务 QWidget 加标题会减少内容空间] → 标题保持单行紧凑，主 Surface 继续滚动；重点组件不设置不可伸缩的固定高度。
- [Provider 输出具有概率性] → 温度保持为 0，逐场景执行结构断言；任一失败使整次验收失败，不通过修改 Parser 或手写结果兜底。
- [进程退出竞态可能误判 PID] → 同时校验 PID、父子关系/启动标识和端口状态，只清理入口实际创建的进程。
- [50 个样本不足以描述长尾延迟] → 首轮只报告平均值与 p50，并保留样本级耗时；需要尾部指标时另行扩大样本量和修订测评方案。
- [导入接口与 Renderer 校验可能漂移] → 服务端、编排链路和测试 Fixture 共用结构/语义规则；前端仍执行独立防御性校验，跨层测试覆盖同一错误样本。
- [导出中断可能留下残缺文件] → 使用 `QSaveFile` 提交临时文件，只有完整写入成功后替换目标。
- [双区布局压缩动态 Surface] → 控制栏设置紧凑最小宽度、分隔条可调，Surface 使用既有双向滚动；三档缩放与批量 DSL 几何测试共同约束。
- [固定种子生成器覆盖有限] → 报告显式保存覆盖矩阵和 seed，新增缺陷复现 DSL 必须进入固定回归语料。
- [文件时间可能因复制而不完全代表构建关系] → 检查只作为防止明显旧构建的轻量门禁；判断不明确时拒绝启动并要求重新受控构建，不增加额外来源系统。
- [删除旧脚本会使仓库外的私人命令失效] → 文档明确新命令；仓库内调用方全部迁移，不保留会继续隐藏问题的兼容包装。

## Migration Plan

1. 先加入运行时路径解析、XDG 目录约定和只读预检模式，在不启动进程的情况下验证现有 Ubuntu 主机资源。
2. 将 Qt 测试 Fixture 定位改为运行时解析，并在两套受控 GCC 构建中执行完整前后端回归，确认不再依赖 `/workspace`。
3. 加入后端生命周期与 `xcb` 启动流程，验证健康检查、SQLite CRUD/摘要、窗口交互和退出清理。
4. 引入静态主题、五类业务标题和 HostShell 折叠诊断区，运行 Qt 行为测试及三档缩放的视觉冒烟。
5. 在操作者提供轮换后的密钥后执行七场景真实 Provider 验收，通过防泄漏检查后更新审计结果，并再次运行 QObject 身份回归。
6. 如运行入口出现问题，可移除或绕过新入口继续使用原受控容器流程；如主题出现问题，可让主题加载失败回退系统样式。两种回滚都不需要变更 Catalog、Schema、数据库结构或业务 API。
7. 提取默认 Surface 单一源，实现三个无状态 Surface 文档接口及后端单元/集成测试，再实现 HostShell 导入、导出和事务式恢复默认。
8. 将 HostShell 改为双区工作台、应用新 token 与字体角色，优化五类组件尺寸策略，并用代表性 DSL 完成三档缩放视觉检查。
9. 移除 LegacyToolboxWindow 的生产源、启动、截图和测试合同，更新 Ubuntu 生命周期测试以只等待单一 HostShell。
10. 增加固定 seed 合法 DSL 生成器与后端/Qt 批量渲染回归，将发现的最小复现样本纳入固定语料。
11. 在七场景门禁通过后运行正式 50 样本基线，生成合法率、平均值、p50 和阶段失败明细，并输出问题处置/兜底清单。
12. 若新增功能需回滚，可保留原 `/compose` 与当前 Surface 事务语义，禁用文档操作和新主题；默认 Surface 与最后有效页面仍作为恢复路径，不恢复第二个窗口。
13. 将现有启动逻辑迁移到 `scripts/start_ubuntu_demo.sh`，加入有限的源码/资源时间检查，并更新两项直接依赖旧入口的 runtime 测试。
14. 删除 `scripts/run_ubuntu.sh`；再次搜索前端/CMake/测试中的 Legacy 引用，只删除确认无调用的旧文件和旧生成物。
15. 更新 `docs/getting-started.md`、`docs/README.md` 及直接引用旧命令的 Ubuntu 文档。
16. 重新受控构建并用新入口启动，确认单一 HostShell、三个文档按钮、新主题和退出清理；失败时修复新入口，不恢复旧脚本。
